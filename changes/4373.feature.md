Added ``zarr.rechunk`` (and ``zarr.api.asynchronous.rechunk``), which copies an
existing array into a new array with a different chunk (and optionally shard)
layout. The copy is planned against a caller-supplied decoded-memory budget
(``max_mem``, in bytes): source and target chunks both count against the
budget, planning fails early with a ``ValueError`` when even one source chunk
plus one target chunk cannot fit, and no axis is ever assembled in memory
beyond what the budget allows. Shards, trailing edge chunks, and unwritten
fill regions are all accounted for, and pure-fill regions are not materialized
as stored chunks. The target keeps the source's shape, dtype, fill value, and
zarr format; compressors (and other codecs) may be changed. A target left
behind by a failed copy is recognizable as incomplete via
``zarr.rechunk_is_complete``. The source array is never modified or deleted.
