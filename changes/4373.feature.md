Added `zarr.rechunk_array`, an entry point that copies an existing Zarr array
to a new location with a different chunk layout (and optionally a different
compressor) while preserving the shape, dtype, fill value, and values of the
array. The copy is bounded by a caller-supplied decoded working-memory budget
in bytes (`max_mem`): at most one decoded source chunk and one decoded target
chunk are held in memory at any time, and a `ValueError` is raised before
anything is written if that minimal unit does not fit. Sharded sources,
boundary chunks, and unwritten fill-value regions are all handled (pure-fill
target chunks are never materialized), and the destination's array metadata is
written last so an interrupted copy is recognizable as incomplete.
