Added an explicit erase truncation strategy to `zarr.Array.resize` and
`zarr.AsyncArray.resize` via a new `erase` keyword argument. When
`erase=True` and the array is shrunk, cells that fall outside the new shape
but inside retained (boundary) chunks are overwritten with the array's fill
value before the new metadata is committed, so a subsequent resize that grows
the array can no longer restore truncated data. Chunks that fall completely
outside the new shape are still deleted, and chunks completely inside the
retained region are never read or rewritten. If the boundary erasure cannot be
written to the underlying store, the resize raises an error reporting the
incomplete truncation and the array keeps its original shape.
