Strictly validate shard indexes in the `sharding_indexed` codec. A matching
index checksum only proves the index bytes are intact, not that the offsets
and lengths inside are legal. Every index-load path (full-shard reads,
index-only partial reads, and the existing-index load before a partial
write) now verifies, before any index-derived byte range is requested, that:
missing chunks use the full `(2**64 - 1, 2**64 - 1)` marker, `offset +
length` does not overflow and lies within the shard's data section (for both
`index_location="start"` and `"end"`), non-empty chunk payloads do not
overlap (the error names both chunk coordinates), and zero-length payloads
only appear when the inner codec chain is not fixed-size. Corrupt indexes
now raise `ValueError` instead of directing reads at the index region or
past the end of the shard.
